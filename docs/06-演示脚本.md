# TripMate Lite · 5 分钟现场演示台本

| 项目 | 说明 |
|---|---|
| 产品 | TripMate Lite · AI 个人旅行助手 MVP |
| 时长 | **5:00**（含开场与收尾） |
| 入口 | http://localhost:5173 （Vite；`/api` 代理到后端 `http://localhost:3000`） |
| 建议路径 | 顶栏 **行程列表** 做主链路；**AI 助手** 收口生成 + 导入 |
| 对齐 | `docs/PRD.md` 附录 A 演示路径 · `docs/API-CONTRACT.md` v1 · `TESTING.md` 抽检①–④ · `AGENT_LOG.md` |

---

## 1. 分时台本

### 0:00 – 0:30　开场（痛点一句话 + 方案）

**画面**：浏览器已打开行程列表 `/trips`，缩放 100%。可见种子行程卡片「成都三日悠闲游」。

**说**：

> 「短途出行前，『去哪、玩什么、花多少』往往散落在聊天和备忘录里——**拼不齐、记不准、超支才发现**。我们做了 TripMate Lite：一条主链路 **建行程 → 列清单 → 记账看预算 → AI 出建议并可导入**，本地无登录，三分钟走完闭环。」

**动作**：鼠标停在顶栏「行程列表」，不要点进 AI 助手。心里记一下列表里已有几张卡片（seed 后至少 1 张）。

---

### 0:30 – 3:30　主链路演示（约 3 分钟）

> 每步格式：**点哪里 / 说什么**。语速偏慢，留 1–2 秒让评委看清金额与徽章变化。

#### ① 列表全景（0:30 – 0:45）

| | |
|---|---|
| **点** | 停留首页「我的行程」：卡片网格（名称 / 目的地 / 日期 / 预算） |
| **说** | 「这是真库里的行程。种子数据是成都三日游，预算 ¥3,000。点卡片进详情，右上角可以改或删——删会级联清掉景点和费用。」 |

**备忘**：不要在主链路里删种子行程。演示用下面新建的青岛卡。

#### ② 新建行程（0:45 – 1:10）

| | |
|---|---|
| **点** | 右上角 **+ 新建行程** → 按表填写 → **保存** → 等 toast「创建成功」 |
| **说** | 「先建一条现场行程。名称、目的地、日期、预算落进 Postgres，刷新不丢。」 |

**现场填写（可照抄）**：

| 字段 | 值 |
|---|---|
| 名称 | `现场演示：周末青岛两日游` |
| 目的地 | `青岛` |
| 日期区间 | `2026-08-22` 至 `2026-08-23`（任意连续两天即可） |
| 预算 | `1500` |
| 备注 | `现场演示`（可选） |

#### ③ 加景点 + 标已去（1:10 – 1:40）

| | |
|---|---|
| **点** | 点刚建的青岛卡片进入详情 → Tab **景点 / 活动** → **+ 添加景点** → 填「栈桥」、类型「景点」、预计花费 `0` → **保存** → 再加「八大关」→ 把「栈桥」的开关拨到 **已去** |
| **说** | 「清单挂在行程下。类型是景点 / 餐饮 / 交通 / 其他；状态只有待去、已去，刷新后还在——不是前端假开关。」 |

**备忘**：拨开关后应出现 toast「状态已更新」；已去行会变灰。

#### ④ 记账 + 超支提醒（1:40 – 2:20）

| | |
|---|---|
| **点** | 切 Tab **费用记录** → 先看上方「预算概览」（已花费应为 ¥0.00）→ **+ 记一笔** 两次 → 抬头看进度条与警告条 |
| **说** | 「费用只做新增和删除，改一笔就是删旧建新。合计是 number 相加，不是字符串拼接。两笔记完会超过 1500，顶部会出现超支提醒。」 |

**两笔记账（合计 ¥1,560.00，超支 ¥60.00）**：

| 名称 | 金额 | 类别 | 发生日期 |
|---|---|---|---|
| 高铁往返 | `580` | 交通 | 行程开始日（或当天） |
| 海边民宿两晚 | `980` | 住宿 | 行程开始日 |

**画面应对**：

- 表格底部合计 **¥1,560.00**
- 预算概览：预算 ¥1,500.00 / 已花费 ¥1,560.00 / 剩余为负数（红色）
- 黄色警告条：**已超出预算 ¥60.00，请注意控制开支**
- 分类标签可见「交通」「住宿」小计

#### ⑤ AI 生成行程建议（2:20 – 3:05）

| | |
|---|---|
| **点** | 顶栏 **AI 助手** → 「从已有行程带入」选 `现场演示：周末青岛两日游（青岛）` → 确认目的地 / 天数 / 预算已带入 → **生成行程建议** |
| **说** | 「表单可以从已有行程带入，避免再填一遍。生成时走 DeepSeek；没 Key、超时或结构校验失败会自动 Mock，接口仍是 200，页面用徽章标明来源——等会儿技术亮点再展开。」 |

**等待（约 10–20 秒，Mock 通常更快）**：骨架屏文案是「正在调用 DeepSeek 生成建议」。期间不要刷新。

**生成后扫一眼**：

1. 绿色 **DeepSeek 真实调用**，或橙色 **Mock 降级** + `fallbackReason`（如「未配置 DEEPSEEK_API_KEY」）
2. 总述 `summary`
3. 时间线「每日安排」（上午 / 下午 / 晚上）
4. 「预算分配」进度条
5. 「旅行贴士」至少 3 条

#### ⑥ 一键导入清单并回详情（3:05 – 3:30）

| | |
|---|---|
| **点** | **一键导入为景点清单** → 确认「导入到行程」是青岛这条 → 可保留默认全选，或只留 3～4 条 → **确认导入** → toast 里点 **查看行程详情** |
| **说** | 「建议不是只读文案：勾选后批量写成景点，状态默认待去。回详情就能和刚才手加的栈桥、八大关排在一起。」 |

**备忘**：toast 文案形如「已导入 N 个景点」。回到详情后 Tab 应在「景点 / 活动」，列表条数 = 手加 2 条 + 导入 N 条。

---

### 3:30 – 4:30　技术亮点（三句话，各约 20 秒）

**画面**：可停在刚导入的行程详情，或口头讲、鼠标停在顶栏。

1. **契约驱动的多 Agent 并行**  
   > 「我们先冻结 `docs/API-CONTRACT.md` v1，再用 Cursor Rules 划死 P/B/F/A/Q 可写目录；前端只认 camelCase，库表 snake_case。所以后端 API、前端页面、AI 模块能并行，而不是互相改字段。」

2. **AI 同构降级**  
   > 「`POST /api/ai/suggest`：有 Key 走 DeepSeek；缺 Key、超时、非 2xx、JSON/schema 失败一律 **200 + Mock**，字段与真调同构。页面徽章是 `source`，旁边是 `fallbackReason`。评审无 Key、甚至断网，主链路仍可演完。」

3. **真库金额与预算聚合**  
   > 「预算概览来自 Postgres 汇总，不是写死卡片。`db.js` 把 NUMERIC 解析成 JS number，避免『100』+『200』变成『100200』。演示里两笔记账立刻反映到已花费、剩余和超支条。」

---

### 4:30 – 5:00　收尾

**说**：

> 「总结：TripMate Lite 用一条主链路把去哪、玩什么、花多少串起来；工程上靠契约 + 目录隔离把多 Agent 压进 3 小时；AI 可真可降级，数据落在真实 Postgres。文档在 `docs/` 和 `TESTING.md`，欢迎提问。」

**动作**：停在青岛行程详情（预算超支条仍在更有记忆点）；双手离开键盘，准备答问。

## 2. 演示前 3 分钟检查清单

开演前逐项打勾：

| # | 检查项 | 怎么确认 |
|---|---|---|
| 1 | **前后端已启动** | 根目录 `npm run dev`；浏览器打开 http://localhost:5173 能出「我的行程」 |
| 2 | **数据库连通且有 seed** | 列表可见「成都三日悠闲游」、预算 ¥3,000.00；刷新不报错。没有则执行 `npm run db:init`（需 `PGPASSWORD`） |
| 3 | **健康检查** | 浏览器或 curl `http://localhost:3000/api/health` 返回 `{ ok: true, ... }` |
| 4 | **浏览器缩放 100%** | Ctrl+0；窗口最大化，顶栏「行程列表 / AI 助手」不被裁切 |
| 5 | **关掉无关标签页** | 只留 TripMate + 可选本台本；关通知弹窗 |
| 6 | **AI 分支已准备** | **主演示优先有效 `DEEPSEEK_API_KEY`**（绿徽章更好看）。被问「没 Key 怎么办」时：`.env` 清空或改成 `sk-invalid` 后**重启** `npm run dev`，再生成一次，确认橙色「Mock 降级」+ 原因文案。无 Key 也能演完整条主链路。 |

可选加练（45 秒）：走一遍「新建青岛 → 加栈桥 → 记一笔 → AI 生成 → 导入」确保按钮未禁用、toast 正常。若时间紧，可只用 seed 成都行程做 AI 带入，跳过新建。

## 3. 评审提问预案（对齐契约 / 技术栈红线）

> 对应 `docs/API-CONTRACT.md` v1、`.cursor/rules/00-global.mdc` 技术栈红线、`docs/PRD.md` 范围与降级策略。回答保持与仓库一致，不临时改口。

### Q1：为什么前后端分仓 Vue 3 + Express，而不是 Next.js 单仓？

- **选型**：Vite + Vue 3 前端；Express 4 + 原生 `pg` 后端；开发期 Vite proxy 把 `/api` 转到 3000。  
- **理由**：赛题技术栈已冻结（Express ^4.21、禁止 Express 5、禁止 TypeScript / ORM）；分目录正好对应 B/F Agent 隔离。  
- **放弃备选**：Next.js 单仓联调快，但会打破栈红线，也让「契约可 curl」的前后端分离叙事变弱。  
- **证据**：`client/` + `server/`；`npm run dev` 用 concurrently 一起拉起。

### Q2：为什么 PostgreSQL，而不是 SQLite / 本地文件？

- **选型**：本机 PostgreSQL；开发库 `tripmate`，测试库 `tripmate_test`。  
- **理由**：费用汇总、级联删除、NUMERIC 金额都要真库语义；测试与演示隔离，避免 seed 被用例打脏。  
- **放弃备选**：SQLite 省安装，但与赛题「Postgres + 金额 number」验收口径不一致。  
- **证据**：`server/db/schema.sql` 外键 `ON DELETE CASCADE`；`npm test` 只打测试库。

### Q3：为什么手写 SQL + `pg`，而不是 Prisma / ORM？

- **选型**：原生 `pg` 连接池；repository 做 snake_case ↔ camelCase。  
- **理由**：3 小时内契约字段少、SQL 可见；避免 ORM 迁移与 Agent 猜 schema。  
- **关键实现**：`db.js` 将 PG NUMERIC（OID 1700）`parseFloat` 成 JS `number`，费用合计不会变成字符串拼接。  
- **放弃备选**：Prisma 对齐成本低，但不在本项目栈红线内。  
- **证据**：`TESTING.md` E-01：`totalSpent === 900` 且 `typeof number`。

### Q4：为什么 REST Route，而不是 Server Actions / GraphQL？

- **选型**：REST `/api/*`；成功直接返回资源，失败统一 `{ error: { code, message } }`。  
- **理由**：契约可 curl、可 Supertest；B 与 F 不看对方代码也能并行。  
- **硬约束**：`POST /api/ai/suggest` 真调或 Mock **一律 200**，不得因模型失败 5xx。  
- **证据**：`docs/API-CONTRACT.md` 冻结声明；前端 `client/src/api/` 按模块封装。

### Q5：为什么接 DeepSeek？没 Key / 断网怎么办？

- **选型**：DeepSeek（OpenAI 兼容）+ **同构 Mock 降级**。  
- **理由**：真实模型加分；兼容协议接入成本低；Mock 的 `days` / `budgetPlan` / `tips` 与真调同一套渲染。  
- **降级触发**：无 `DEEPSEEK_API_KEY`、超时（默认 15s）、HTTP 非 2xx（含 429）、非法 JSON、schema 校验失败。  
- **安全**：Key 只在根目录 `.env`，gitignore，不进客户端。  
- **证据**：页面绿/橙徽章；`server/src/ai/index.js` 的 `fallbackReason`；`tests/ai.test.js` 强制无 Key 仍 200。

### Q6：为什么 Element Plus？为什么没有登录 / 地图？

- **选型**：Element Plus **全量引入**（禁止按需插件）；无登录；不做地图 / 支付 / 社交 / RAG。  
- **理由**：3 小时要的是数据闭环和 AI 降级，不是动效或交易系统；单用户本地 MVP，加鉴权等于否定产品前提。  
- **费用无编辑接口**：改费用 = 删除 + 新建——写在 PRD / 契约，避免被判成缺功能。  
- **补充限制**：无语义搜索、无并发冲突处理、无 Playwright E2E（时间盒内以后端契约测试为主）。与 `PRD.md` §2.2、`TESTING.md` §6 一致。

## 4. 超时与翻车预案（口袋卡片）

| 情况 | 处理 |
|---|---|
| AI 生成超过约 20 秒仍转圈 | 口播「超时会降级 Mock」；若一直 pending，切回已生成过的结果或重启后再用无 Key 秒出 Mock |
| 绿徽章变橙 / 一直 Mock | 不道歉成故障：指出徽章旁的 `fallbackReason`，强调「主链路仍可用」；有 Key 时确认已重启 dev |
| 新建行程失败 | 立刻改用种子「成都三日悠闲游」继续加景点 / 记账 / AI 带入 |
| 超支条没出现 | 确认两笔合计 > 预算 1500；或再记一笔「现场购物」`200` 餐饮 |
| 导入后看不到新景点 | toast 点「查看行程详情」；或顶栏回列表再点进青岛卡，看「景点 / 活动」Tab |
| 被追问地图 / 路径规划 | 「3 小时红线：地图 SDK 与闭环无关；清单 + 记账足够演示去哪玩什么花多少」——与 PRD §2.2 一致 |
| 被追问登录鉴权 | 「单用户本地、契约写明无 Token；生产再补鉴权限流」——与全局规则一致 |
| 被追问费用为什么不能改 | 「MVP 明确无 PUT/PATCH；改费用 = 删旧建新，避免被当成漏做」 |
| 列表空白 | `npm run db:init` 未跑或连错库；不要现场建库，改口述 seed 流程并展示空态「还没有行程…」（空态不白屏也是验收点） |
| 演示超时 | 砍掉「导入」：AI 出徽章 + 日程即可（PRD：P1 导入可砍，AI 仍及格） |

## 5. 备用 3 分钟压缩版

若只给 3 分钟（对齐 PRD 附录 A），按此砍：

1. **0:00–0:20** 开场痛点 + 指向列表上的成都种子卡。  
2. **0:20–0:50** 新建青岛行程（或直接进成都详情，省 30 秒）。  
3. **0:50–1:20** 加 1 个景点并标已去（只加一条也够讲持久化）。  
4. **1:20–1:50** 记 2 笔费用，指超支条。  
5. **1:50–2:40** AI 生成，指绿/橙徽章。  
6. **2:40–3:00** 口头说「可一键导入清单」；有时间再点导入，没时间收尾。
